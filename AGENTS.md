# AGENTS.md — ARCHi

ARCHi is a companion product with several intentionally separate state owners. Read `START_HERE.md` before changing code.

## Core doctrine

1. Native Swift remains the authority for assistance, permissions, working-copy state, kept lessons, preferences and saved companion development.
2. Unity is presentation/practice. Do not make it a second memory, identity, assistance-client or canonical-save owner.
3. The retained TypeScript Journey/battle engine keeps its current domain ownership unless a deliberate migration contract says otherwise.
4. Marketplace state is local creator/account/catalog/inventory state. It does not establish payment, scarce editions, creator endorsement or Internet ownership.
5. Qwen, Codex and Compare are bounded inference lanes. They do not own identity, memory, permissions or accepted document state.
6. Reading, reviewing or generating a proposal must not implicitly Apply, Keep, award development, or persist private context.
7. External-copy permission and freshness/cancellation fences are security boundaries, not UX suggestions.
8. Source validation, runtime acceptance, redistribution review, signing and release declaration are separate evidence layers.

## Before editing

Identify:

- the subsystem owner;
- the state that can change;
- whether the operation is local, external, or a presentation-only projection;
- the permission/admission boundary;
- the smallest focused test;
- any asset/license or private-data implication.

## Sensitive boundaries

Never commit:

- personal profiles or private conversations;
- kept lessons or user documents;
- credentials/session material;
- model weights;
- generated private evidence;
- editable/private authoring originals unless explicitly admitted for redistribution.

Do not claim withheld or absent artwork is licensed merely because code references it.

## Verification

Use the repository's own commands from `START_HERE.md` and `README.md`. Report skipped/opt-in suites separately. A successful build is not proof of visual/runtime/accessibility/distribution behavior.

## Cross-repo / GSV rule

`.gsv/project.yaml` describes ARCHi's role in the wider lattice. It does not transfer ARCHi product authority to Kilo_Core or any wrapper. Cross-repo integrations must consume explicit contracts and preserve ARCHi's local ownership boundaries.
